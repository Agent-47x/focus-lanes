# House rules

*Global working preferences.* Everything under **Rules** is pushed by the daily build into every project's
`CLAUDE.md` (between the `HOUSE RULES` markers) and into every `PLAYBOOK.md`, so every session in every folder
sees it. Keep it short — it is loaded into every session. Domain-specific rules belong in the playbooks.

> STARTER SET — these are examples. Replace them with how *you* want work done; the next build propagates the change.
> New rules also arrive here automatically from `- [global] …` lines under `## Promote` in any project's `MEMORY.md`.

## Rules
- Dates are ISO (YYYY-MM-DD); amounts carry their currency; file and folder names are quoted exactly.
- Handoff files (STATUS, LOG, MEMORY) are factual and short: state, actions, dates, facts — no conversation summaries.
- Only the owner changes a project's status, lane or priority; suggest, then ask.
- Never write secrets into any file; never paste credentials into notes.
- Deliverables are saved beside their sources with clear names; nothing new at the root of the workspace.
- Before producing a deliverable or making a decision, read the project's `PLAYBOOK.md`; a two-line question does not need it.
- Check the real date before writing dates into deliverables or handoff files.
